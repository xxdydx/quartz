## why transformers?

before 2017:
- the dominant architecture for language related sequence tasks (e.g. translation, summarisation, speech) were RNNs/CNNs.
- RNNs/LSTMs processed input tokens sequentially -> inherently slow and hard to parallelise.
- **CNNs** used local receptive fields → struggled with _long-range dependencies_.

the transformer helps how?
- capture dependencies between any two tokens in the sequence (even between the first and the third last word in the sequence, for example!)
- train fully in *parallel* across all positions
- this allows for scaling, much better than RNNs!


## core intuition

the transformer reads all the tokens in the sequence at once

each token dynamically attends to every other token in the sequence and decides:

> how much should i care about this other word when trying to understand what this sequence means?

this is done through the **attention mechanism**— a weighted averaging of all other tokens, where the weights depend on the contextual relevance of the token.

- **decoder** — generates output sequence, attending to previous outputs and encoder representations.

modern models make use of encoders, for embedding models like BERT and decoders, for text generation models like GPT.

## positional encodings

- a transformer processes tokens in *parallel*, so without an explicit mechanism, token order becomes nonexistent— which is why we have positional encodings!
- the model must be told which tokens come first, which came after, and how far tokens are from one another.
- positional encodings inject order and distance information into token representations before the transformer layers (like attention & feed-forward network)
- **two** main types of positional encodings— absolute (each position index has a unique representation) and relative (each position is defined relative to another token)

### guidelines for a good encoding method
- **unique** — each position should have a distinct encoding
- **consistent** — the encoding of a specific position should be the same regardless of the total length of the sequence
- **bounded** — the values generated by the positional encoding function stay within a reasonable range

**some not so good positional encoding methods**
- index of the token — it is unique and consistent, but not bounded (can go up to infinity)
- index of the token scaled by the length of the sequence — it is unique and bounded, but not consistent (e.g. 5th token of a 10-token long sequence is different from 5th token of a 1000-token long sequence)
### sinusodial positional encodings
- absolute positional encoding; used in the original transformer paper
- uses fixed sine & cosine waves of different frequencies
- each position, $pos$, is mapped to a vector of dimension $d$
```python
PE(pos, 2i) = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```
- if two tokens are close in the sentence, their positional encodings are similar. conversely, if two tokens are further apart in the sentence, their positional encodings differ more.
- con of this is that tokens that are far apart can have strong relationships too, which causes the model to struggle with longer context. 

```python
"The cat that chased the mouse and ran across the garden sleeps."
```
example: cat (noun) & sleeps (verb) are 9 words apart

### relative position encodings (T5, Transformer-XL)
- the model learns vectors that represent distance between tokens, not their absolute positions.
- injected inside the attention score rather than added to token embeddings.


### rotary positional embeddings (RoPE) (GPT-NeoX, LLamA, DeepSeek)
- the query and key vectors are rotated in feature space according to token position
- rotation angle increases with position, so later tokens point in different directions than earlier ones
- attention compares q and k, so the dot product naturally reflects _how far apart tokens are_
- therefore, **relative order** emerges without storing explicit position values
- handles long sequences better than absolute positional embeddings
- used in most modern LLMs because it scales well and preserves long-range dependencies

### when to use which

| method           | strengths                                           | limitations                                | used in                         |
| ---------------- | --------------------------------------------------- | ------------------------------------------ | ------------------------------- |
| learned absolute | simple, effective for short text                    | does not scale well beyond training length | bert, gpt-2                     |
| sinusoidal       | extrapolates beyond training length                 | fixed pattern, weaker linguistic alignment | original transformer            |
| relative bias    | captures syntactic structure well                   | more complex to tune                       | t5, transformer-xl              |
| rope             | efficient, stable long context, used in modern llms | needs scaling tricks for ultra-long input  | llamA, gpt-neox, deepseek, qwen |
## encoder

each encoder layer has:
- **multi-head self attention** — learns context between all tokens in the input sentence
- **[[feed forward network]]** — applies two linear transformations with a ReLU in between, to mix and transform features
- **residual connections + layer normalisations** — to stabilise gradients and preserve information flow (like in a typical neural network)

basically, each layer:
- takes input `x` (token embeddings).
- computes `y = LayerNorm(x + MultiHeadSelfAttention(x))`
- then `z = LayerNorm(y + FFN(y))`

## decoder

each decoder layer is similar, but with:
- **masked self-attention** (tokens cannot see future words)
- **cross-attention** (attends to encoder outputs)
- **feed-forward + residual + layernorm** (same as before)

this allows the decoder to generate text one token a time, while conditioning on the entire input.


## advantages
- **parallelisation**: full-sequence processing during training.
- **global context**: long-range dependencies easily captured.
- **scalability**: scales well with compute and data.
- **transferability**: learned representations generalise across tasks.

## limitations

- **quadratic complexity**: attention cost scales as O(n²) with sequence length.
- **context limit**: cannot handle very long documents efficiently.
- **lack of inductive bias**: unlike CNNs (locality) or RNNs (sequence continuity)

## what has happened since that 2017 paper?
- **[[decoder-only transformers]]**: GPT series, LLaMA, PaLM (for text generation).
- **encoder-only transformers**: BERT, RoBERTa, DistilBERT (for classification/embedding tasks).
- **encoder-decoder**: T5, BART, FLAN (for translation, summarisation, instruction-tuning).


extensions include:
- **Sparse attention patterns** (Longformer, BigBird)
- **Memory tokens / recurrence** (Transformer-XL)
- **Mixture-of-experts layers** (Switch Transformer)
- **Rotary positional embeddings** (RoPE in LLaMA, GPT-J)
